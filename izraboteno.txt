================================================================================
ШТО Е ИЗРАБОТЕНО — MNSIM IMC + нови метрики
Проект: benchmark-neuromorphic (Laravel + Python + PostgreSQL + Docker)
Апликација: http://localhost:8080
================================================================================

Цел: пет архитектури (CPU Baseline, GPU Baseline, Intel Lava / Loihi,
IBM NSCS / TrueNorth, MNSIM IMC) и проширени метрики во PostgreSQL,
табели и графикони, без да се скршат постоечките backend-и и старите метрики.

Дополнително по основната задача: soft delete (deleted_at), приказ на
бројки во табели со 4 децимали, и SQL export за pgAdmin 4.

Ако Docker не работи, во папката benchmark-neuromorphic изврши:

    docker compose up -d

потоа отвори http://localhost:8080


--------------------------------------------------------------------------------
1. TrueNorth останува
--------------------------------------------------------------------------------

ШТО Е НАПРАВЕНО
- ibm_nscs останува во python/cli/run_benchmark.py (BACKENDS).
- python/backends/ibm_nscs.py и python/simulators/truenorth_lif.py не се
  тргани; логиката на TrueNorth симулацијата е иста.
- database/seeders/DatabaseSeeder.php сè уште го има редот
  ibm_nscs / IBM NSCS / TrueNorth.
- Methodology страницата сè уште го опишува TrueNorth.
- TrueNorth е neuromorphic (spikes). MNSIM IMC е посебна, петта архитектура
  (in-memory computing), не замена за TrueNorth.

КАКО ДА СЕ ПРОВЕРИ (секција 1)

Прво направи:
- docker compose up -d (ако не е веќе стартувано)
- отвори http://localhost:8080

Каде да погледнеш:
1. UI: Start new benchmark — во Architecture мора да стои
   IBM NSCS / TrueNorth (не смее да исчезне).
2. UI: Methodology — текстот за IBM NSCS / TrueNorth сè уште постои.
3. База (опционално): табела architectures — редот slug = ibm_nscs постои.

Што да очекуваш:
- 5 архитектури во dropdown (4 стари + MNSIM IMC).
- Старите completed TrueNorth runs остануваат во History (освен ако се
  soft-избришани од UI).


--------------------------------------------------------------------------------
2. MNSIM + backend адаптер (петта архитектура)
--------------------------------------------------------------------------------

ШТО Е НАПРАВЕНО
- MNSIM не е pip пакет; вклучен е vendor код во python/vendor/mnsim
  и наш адаптер што го поврзува со CLI.
- python/backends/mnsim_imc.py — run(X_train, y_train, X_test, y_test)
- python/simulators/mnsim_adapter.py — PIM/IMC модел за latency/energy
  (crossbar проценка). Класификацијата на CICIDS/UNSW е sklearn MLP,
  затоа што MNSIM е наменет за CNN/CIFAR, не за IDS CSV директно.
- CLI: BACKENDS["mnsim_imc"] = mnsim_imc.run
- Seeder: slug mnsim_imc, име MNSIM IMC, is_neuromorphic = false
- Methodology: нова точка за IMC / MNSIM
- Python во Laravel app контејнерот: BENCHMARK_PYTHON=/usr/local/bin/python3
  (за да има sklearn, psutil, torch). UI не го користи посебниот python
  Compose сервис за Process повиците.

КАКО ДА СЕ ПРОВЕРИ (секција 2)

Прво направи:
1. docker compose up -d
2. Refresh на http://localhost:8080/benchmarks/create (Ctrl+F5)

Каде да погледнеш:
1. UI: Architecture dropdown — 5 опции. Новата се вика MNSIM IMC.
2. UI: Methodology — IMC користи MNSIM + адаптер; TrueNorth е одделно.
3. База: architectures — 5 реда. Нов: slug = mnsim_imc.
   Стариот ibm_nscs сè уште постои.

Што да очекуваш:
- Можеш да избереш MNSIM IMC + CICIDS и Start.
- Run-от треба да заврши со status completed (може да трае подолго од CPU).
- Ако падне, на Show ќе има error — тоа не е нормално.


--------------------------------------------------------------------------------
3. Нови метрики: Accuracy, Recall, Precision, ROC-AUC, Memory, CPU/GPU
--------------------------------------------------------------------------------

ШТО Е НАПРАВЕНО
Python:
- python/metrics/accuracy.py — F1, FPR + accuracy, precision, recall,
  roc_auc, roc_curve (FPR/TPR точки)
- python/metrics/resources.py — memory (MB), CPU %, GPU % (0 без CUDA)
- python/metrics/bundle.py — pack_metrics()
- Сите backend-и (CPU, GPU, Lava, TrueNorth, MNSIM IMC) ги враќаат
  старите и новите клучеви
- python/db/writer.py — INSERT/UPDATE ги вклучува новите колони
- psutil во python/requirements.txt

Laravel / DB:
- Migration: accuracy, precision_score, recall, roc_auc, memory_mb,
  cpu_utilization, gpu_utilization, roc_curve (JSON)
- Старите колони НЕ се бришат: f1_score, latency_ms,
  throughput_ops_per_sec, energy_joules_per_op, false_positive_rate
- BenchmarkMetric model: fillable + casts
- Show страница: стари 5 картички + нови + ROC chart

КАКО ДА СЕ ПРОВЕРИ (секција 3)

Прво направи:
1. Миграциите се веќе применети во Docker.
2. Пушти НОВ benchmark (барем еден). Старите runs немаат пополнети нови
   колони (празни / 0) — тоа е нормално.

Каде да погледнеш:
1. База: колоните на benchmark_metrics — и старите и новите.
2. UI Show на НОВ completed run: Accuracy, Precision, Recall, ROC-AUC,
   Memory, CPU/GPU % покрај F1/FPR/Latency.
3. UI Show: график ROC curve (линија).

Што да очекуваш:
- Accuracy / Precision / Recall / ROC-AUC: меѓу 0 и 1
- Memory: MB (на пр. десетици до стотици), не 0 кај нов run
- CPU utilization: 0–100
- GPU utilization: 0 во Docker без CUDA (точно за CPU/Lava/TrueNorth/IMC);
  >0 само ако GPU backend работи на вистинска GPU
- Стар TrueNorth run на Show: старите метрики се гледаат; новите може
  да се празни до повторно пуштање

6. Soft delete (deleted_at) — дополнително
--------------------------------------------------------------------------------

ШТО Е НАПРАВЕНО
- На табелите datasets, architectures, benchmark_runs, benchmark_metrics
  последна колона е deleted_at.
- Eloquent SoftDeletes на сите четири модели.

3. База: редот во benchmark_runs сè уште постои; deleted_at НЕ е NULL.

Што да очекуваш:

--------------------------------------------------------------------------------
Како да се импортира database.sql во pgAdmin 4
--------------------------------------------------------------------------------

Фајл: database/database.sql
Ова е обичен SQL скрипт (шема + податоци + индекси + FK), не .backup.
НЕ користи Restore во pgAdmin за овој фајл.

Чекори:
1. Отвори pgAdmin 4 и поврзи се на PostgreSQL сервер.
2. Десен клик на Databases -> Create -> Database.
   Име: benchmark
   Encoding: UTF8
   Потврди Save.
3. Десен клик на новата база benchmark -> Query Tool.
4. Во Query Tool: File -> Open -> избери
   benchmark-neuromorphic/database/database.sql
5. Изврши го скриптот: копчето Execute / F5.
6. Refresh на базата (F5 на дрвото) и отвори Schemas -> public -> Tables.
   Треба да ги видиш:
   - architectures
   - datasets
   - benchmark_runs
   - benchmark_metrics
   - migrations

Важно:
- Query Tool мора да е отворен ВРЗ базата benchmark, не врз postgres.
- Скриптот почнува со DROP IF EXISTS, па ги создава табелите одново.
  Ако го извршиш повторно врз иста база, постојните табели ќе се заменат.
- Ако добиеш грешка за права, корисникот во pgAdmin треба да може да
  прави CREATE/DROP TABLE на таа база.
- Docker базата на :5432 (корисник benchmark / лозинка secret) е посебна
  од локалниот PostgreSQL во pgAdmin, освен ако pgAdmin е поврзан токму
  на Docker (host localhost, port 5432, database benchmark).
